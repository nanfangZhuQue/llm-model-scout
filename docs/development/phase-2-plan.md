### 历史与对比的实现约定

- **数据写入。** 按运行、入口发现和模型结果建表。明细用运行 ID 与任务内序号标识，避免脱敏后的名称冲突。检查点事务同时更新明细和计数，终态与最终报告一并提交。SQLite v3 增加复测去重记录，可自动迁移 v1 和 v2。持久化字段采用允许清单，排除凭据、代理密码和原始响应正文。
- **重启与限额。** 结束任务可从 SQLite 读取。启动时把遗留活动任务标记为中断，有已保存结果时可下载部分报告。复测由用户显式触发。每个数据目录由一个 Agent 持有写入锁，运行期请求额度从 Agent 启动时计数。磁盘按 `max_history` 保留最近结束的终态任务，活动任务不占用终态配额。
- **可比条件。** 对齐稳定的服务商 ID、入口 ID、协议、模型 ID、探测能力，比较实际生效的 profile、token 上限及连接修订。记录筛选范围、候选来源与发现完整性。托管连接可用修订号标识配置变化；旧 TOML 入口缺少可核验的凭据修订时显示「凭据变化未知」。路由信息仅在上游提供可验证字段时记录。
- **目录与验证。** 两次可比且完整的 API 发现才能判定目录新增或缺少某项。手选扫描、截断分页或发现失败时显示覆盖范围。模型状态变化需要两次都有已执行的验证结果；更换参数或连接后单独标注条件变化。复测记录指向原任务，原报告可独立重读。

### P1 端到端验收样例

1. 在临时目录用双协议 mock 建立首轮报告。一个入口包含 A、B，另一入口也返回名为 A 的模型。
2. 重启 Agent。让首个入口的 A 从有效文本变为 403，B 继续通过，第二个入口的 A 继续通过。对比页应准确定位唯一的通过转失败项。
3. 单选变化项，设置零重试。核对 mock 计数只增加一次聊天请求，并能从复测记录返回来源报告。
4. 另做一次分页中断和一次手选子集扫描。缺少的目标显示发现不完整或本次未测。再次重启，可查询原始、对比所用及复测运行，并下载原报告。
