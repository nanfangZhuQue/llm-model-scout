# 变更记录

记录已确认变更；应用版本与文档更新独立管理。

## 2026-11-26 · T11 工具调用探测（REQ-032）

- CLI/TOML、交互菜单、Agent 和工作台可显式选择工具调用。三种协议发送同一个合成函数的定义，验证合法调用、调用次数、工具名和参数。
- 探测在验证返回的调用指令后结束。预算预览不发上游请求，历史、对比、复测和报告按能力区分。调用原文和参数不写入报告。

## 2026-11-26 · T10 结构化输出探测（REQ-032）

- CLI/TOML、交互菜单、Agent 和工作台可显式选择结构化输出。三种协议按各自字段发送固定 JSON Schema，再本机验证完整 JSON 和字段类型。
- 分别诊断无效 JSON、Schema 不匹配、拒答和截断。预算按实际目标与尝试计数，预览不发上游请求。
- 历史与导出标识探测能力，比较和复测保留所选能力。原始输出不写入报告。
- 拒答块和无效停止原因不会被合法 JSON 掩盖。XLSX 将服务商名称、模型 ID 等值作为文本单元格保存。

## 2026-11-26 · T09 SSE 流式文本探测（REQ-032）

- CLI/TOML、鉴权 Agent 和工作台可显式选择流式文本，覆盖 OpenAI Chat、OpenAI Responses 和 Anthropic Messages。扫描预算按目标和请求尝试计数。
- 流式验证等待协议完成事件，区分空流、完成前断连、超限、无效事件及用户取消。沿用现有超时、重试和并发限制，报告不保存原始流文本。
- 历史和报告标记流式能力。对比按能力配对，复测沿用来源能力，CSV 和 XLSX 继续使用原有列。

## 2026-11-26 · T08 Responses 非流式文本探测（REQ-031）

- 新增显式 `openai_responses` 入口。CLI/TOML、托管服务商、Agent 和工作台支持独立选择，Chat 与 Responses 同名模型分别发送请求、计数和入报告。
- Responses 使用 `input`、`max_output_tokens`、`stream=false` 和 `store=false`。验证区分拒答、空文本、未完成和响应对象报错，报告保存固定诊断和白名单停止原因。
- 托管服务商可同时保存三种协议。Web 在目录和结果中支持协议筛选，Agent 支持同时对三个入口提交手选目标。

## 2026-11-26 · T07 快速诊断（REQ-030）

- 工作台提供「验证指定模型」和「批量验收」。快速验证使用单个入口、一个显式模型、一次请求预算和零重试。
- 鉴权 `POST /scans/preview` 使用创建任务的解析规则，显示各入口 Token 上限、已知目标或待发现状态、任务及共享预算和可能的请求上界。工作台表单及目录批量操作都展示预览。
- 结果表展示 HTTP 状态、实际尝试次数和诊断。新增 Windows 模拟服务回归覆盖发现接口 404、上游 401/429、请求超时及 HTTP 200 空文本。

## 2026-11-26 · T06 按差异复测（REQ-029）

- 工作台可勾选单个共同入口中的差异和未测模型。鉴权 `POST /scans/retest` 重新校验目标，沿用本次来源保存的探测参数，并使用当前连接与共享请求配额。
- 连接变更时显示脱敏差异，确认后创建任务。复测任务与 JSON 报告保留两条来源任务和入口 ID。
- SQLite schema 升至 v3，任务与请求 ID 一并提交。相同请求在任务保留期间跨重启去重。

## 2026-11-26 · T05 两次扫描对比（REQ-028）

- 新增鉴权 `GET /scans/compare`。仅对比同一服务商下入口 ID 和协议一致的两条终态记录，跨重启读取历史快照。
- 工作台可指定基准与本次任务，按共同入口查看原始验证结论、条件变化、目录覆盖及未测模型。条件已变或必需字段无法确认时，保留观察值并标注原因。
- 完整且可比的 API 目录显示新增和本次未列出。手选或部分发现保留覆盖信息。对比为本地读取，报告格式和请求预算沿用既有契约。

## 2026-11-26 · T04 历史查询与下载（REQ-027）

- SQLite 历史 schema 从 v1 事务迁移到 v2。现有鉴权列表、详情和下载可读取跨会话历史，列表新增服务商精确筛选与选项。
- Web 任务列表可分页和筛选已改名或删除服务商的任务。支持查看中断记录和下载其中已保存的结果。
- `--max-history` 默认保留 50 个终态任务，启动恢复和每次任务终结时清理旧记录及明细。普通 Agent、desktop 和 `start-web.bat` 均可设置该上限。
- 完整报告使用原保存数据。部分 JSON 记录 `scan.partial=true`，未知请求数为 `null`。部分文件名和 XLSX 状态明确标注，历史读取和下载不产生上游请求。

## 2026-11-26 · T03 保存任务历史（REQ-027）

- Agent 在用户数据目录保存 SQLite 历史。记录包括任务摘要、脱敏探测条件、入口发现和模型结果。数据库在首次启动时创建，schema 版本为 1。
- 检查点与进度一同提交，正常结束时原子写入终态与报告。启动时将上一进程遗留的活动任务标为 `interrupted`，保留已提交结果。
- 一个 Agent 持有同一数据目录的历史写入锁。并行实例可使用各自的数据目录。T04 负责跨会话查询、下载和保留策略。

- Web、CLI verbose 和交互菜单显示候选数及实际验证进度。仅发现任务显示候选数，取消和预算耗尽保留已获得的验证结论。

## 2026-10-08 · 0.6.1 体验优化（REQ-021—024）

- Web UI任务详情新增实时进度条：运行中按“已完成/已发现候选”估算并明确标注，总量确定后按目标总数计算，任务结束置满为绿色。

- “下载 CSV”改为“下载 XLSX”：新增openpyxl依赖与`format=xlsx`报告接口；表头去三列（CSV架构版本/工具版本/建议）、枚举值译为中心词中文、延迟与耗时转秒、时间戳本地化到秒、冻结首行加筛选、通过行整行绿色标注；错误信息保留原文，JSON/CSV原值不变。

- CLI `--pretty`：scan/verify/models 新增彩色表格汇总（状态/错误分类/汇总卡片均高亮），stdout 仍输出 JSON，自动化脚本零影响。

- Agent 启动体验：新增 `--token` 自定义会话 token，启动成功 JSON 输出直接包含 `token` 字段，无需额外读取文件。
- 交互模式进度百分比：`interactive` 选“测试全部”时实时显示 `进度: N/M (P%) 入口:模型 -> 状态`，不再卡住无反馈。
- 终端编码健壮性：Rich console 统一使用 ASCII 兼容字符，Windows 终端无乱码。
- 候选列表筛选框与操作按钮改为flex布局，聚焦高亮不再重叠。
